Código de Conduta

Este projeto e todos os que nele participam regem-se por um Código de Conduta. Ao colaborar, espera-se que você trate todos os membros com respeito, cordialidade e inclusão. Comportamentos inaceitáveis podem resultar na exclusão do projeto.

Como Posso Contribuir?


Reportar Bugs (Erros)

Antes de criar um novo relatório de erro, verifique a lista de issues abertas para evitar duplicados.
Ao abrir uma nova issue de erro, inclua:
• Título claro e descritivo resumindo o problema.
• Passos exatos para reproduzir o erro.
• Comportamento observado vs. Comportamento esperado.
• Ambiente utilizado (Sistema Operacional, versão da linguagem/framework, navegador).
• Logs ou trechos de código relevantes.

Sugerir Melhorias e Funcionalidades

• Utilize as issues para propor novas ideias ou melhorias.
• Descreva claramente por que essa funcionalidade seria útil e como ela se enquadra no propósito do projeto.

Contribuir com Código

1. Faça um Fork do repositório.
2. Crie uma branch para a sua alteração:bash
git checkout -b feature/nome-da-sua-feature
Use o código com cuidado.
3. Faça as alterações no código respeitando os padrões do projeto.
4. Execute os testes (se aplicável) para garantir que nada foi quebrado.
5. Faça o Commit com mensagens claras e objetivas (ex: fix: corrige erro no carregamento do perfil).
6. Envie para o seu Fork:bash
git push origin feature/nome-da-sua-feature
Use o código com cuidado.
7. Abra um Pull Request (PR) direcionado à branch de desenvolvimento principal (develop).

Guia de Estilo e Convenções

• Escreva código limpo, comentado quando necessário e legível.
• Siga as convenções de linting/formatação já configuradas no repositório (ex.: execute npm run lint ou equivalente antes de submeter).
• Escreva testes unitários para novas funcionalidades sempre que possível.

Processo de Pull Request

• O seu Pull Request será revisado pela equipe principal assim que possível.
• Poderão ser solicitadas alterações ou ajustes no código antes da aprovação.
• Após a aprovação, o PR será integrado (merged) à branch principal.
Se precisar de ajuda para adaptar este modelo ao seu projeto específico (como definir regras de linting, testes ou adicionar diretrizes de tradução), diga-me qual é a linguagem/tecnologia do seu projeto!
